# Source-bound selected NPC factory and birth

This component prepares the real `enemy_2133_shdopl` and `enemy_3001_upeopl` inputs, then executes a staged selected Enemy Spawn/Init/Born order. It does not accept an externally initialized MOVE enemy. Unity allocation, pooling, Awake/reset, runtime controller instances, route getters/cursor construction, mode/ability effects, registration, visual state hooks and movement are mandatory explicit providers. No game process was started, injected, modified or contacted.

The original GameAssembly SHA256 is `583b04ff4d1b1a4b35eaf09d77d936408c25447c9e345ef0463d814b6a123fc5`; metadata SHA256 is `d3fede171f92740a6f5dc053c58c7013d3c962db764ad1f05cbe977c074fcd1f`. Five fresh entries have sixteen imported ranges. Eighteen previously recovered entries have fifty-five ranges. Independent original `.pdata` / recursive `UNWIND_INFO.CHAININFO` verification covers all seventy-one imported ranges and fourteen additional raw ranges, twenty-eight raw functions in total. Both short comparisons are reviewed straight-line leaves through RET, not guessed padding bounds. `source_audit.json` records complete intervals and file offsets. A completed decompilation alone is not treated as proof of every expression.

The reviewed dispatch is BattleController.CreateEnemy route overload `0x180621070` → BattleFactory.CreateEnemy `0x1808e9170` → virtual slot231 Enemy.Spawn `0x180a750d0` → virtual slot236 Enemy.Init `0x180a6e450` → virtual slot24 Enemy.Born `0x180a6b290`. The factory's resource/pool/Unity parent and Transform calls are retained as allocation receipts. The component refuses hidden-origin, dummy, unsupported motion correction, unknown hotfix or global numeric modifier paths. A receipt must identify the exact prefab bundle SHA and Enemy MonoScript. Prepared objects must be the same immutable objects returned by `prepare_enemy`; constructed/replaced preparations cannot substitute arbitrary HP or delay.

The resource inputs are copied from the pinned full Mono rule subtrees, real original map references and EnemyDB levels. Both selected enemies have original map level0 references. All undefined optional overwrite fields retain `m_defined=false`; shdopl's talent Blackboard string overwrite remains effective without turning its undefined attribute zeros into values. `prepare_enemy` checks the original source pins, exact derived prefab equality, map ref and DB levels before resolving.

The native initialization order matters. Enemy.Options is stored before AssignData. `unharmful` sets lifePointReduce to zero in AssignData; it does not change HP or BObject.isDisappeared. Entity.Init prepares attributes/SP/timers, calls BObject.Init and its virtual OnInit/OnPostInit, and only then writes full HP from maxHP. BObject's `+0x24` is **inited**, `+0x25` borned and `+0x26` isDisappeared. Enemy.OnInit attaches its valid root talent while inited is still false; Unit.OnPostInit and BObject.Init then write enabled/inited. Cursor construction occurs after Entity.Init. The factory retains this order rather than supplying a ready-made object.

BObject.Born invokes OnBorn before writing borned. Entity.OnBorn starts BORN6, emits Entity event0 and dispatches BuffContainer.OnOwnerBorn. That Buff event is **event12, not Buff.OnStart/event0**. Unit.OnBorn then calls RegisterUnit, attaches common and dynamic Abilities, emits controller OnUnitBorn and dispatches BuffContainer.OnOwnerPostBorn/event35. Enemy.OnBorn's controller/face/effect/script/logger tail follows. Only after return is borned written. Common NeutralTag Buff creation therefore belongs to the common Attach phase with inited=true; its empty Start can run immediately. Talent Buffs attached during OnInit were inited=false and may begin on their first native Buff Tick. The new factory exposes separate phases for both. A review of the root integration found premature common Buff creation; root moved it to the common birth Attach phase and added explicit PostBorn35 delivery and assertions.

BornState.OnEnter plays its animation before assigning the timer. Its Single GT helper `0x1866e4c50` computes `a > binary32(b+epsilon)`, with exact PE epsilon bytes `acc52737`, value `9.999999747378752e-06`. With the selected prefab flagfalse/null hotfix branch, Enemy.get_delayToBorn reads Single at `+0x310`. Values above that epsilon become `FP.from_float32(delay)`, otherwise FP0. BornState.OnTick subtracts FP dt then calls `0x185ed91e0`, exact bytes `483bca0f9ec0c3`: **signed raw remaining <= 0**, with no MathUtil.EN5 epsilon. Its DEFAULT request resolves to MOVE1 through an explicit FSM admission provider. Exit effect/tile-update and Move.OnEnter are external phases around the local state write. A MOVE Tick occurs on the following state Tick, not the transition Tick.

At dt raw143165440, zero-delay upeopl transitions on its first state Tick and moves only on the next Tick. One-second shdopl remains BORN after thirty such deltas and transitions on Tick31. This is a kernel result under the explicit provider context, **not a complete shdopl birth scenario**. A synchronous passive state transition is retained and never overwritten with MOVE; a later tick outside BORN/MOVE is rejected. In particular shdopl's active summon/hidden path can require BORN6→DISAPPEAR11 and is not closed by the old v8 MOVE-only restoration component.

Public API: `prepare_enemy(dataset,key)` → `PreparedEnemyInputs`; `EnemyFactoryRuntime(context,callbacks,clock)` → `allocate(prepared,UnityAllocationReceipt)` → `spawn(actor,PreparedFactoryRoute,typed SummonOptions)` → `tick_birth(actor,FP)`. `FactoryEnemy` subclasses the existing NpcEntity so Buff ObjectPtr, the factory, lifecycle and Scheduler can retain the same identity. `fsm_transition` is admission-only and must not itself mutate state or execute hooks. Named receipt phases record provider sources. `tests/test_enemy_factory.py:FactoryFixture` supplies a concrete test-only constructor, not a native allocation example.
