# Resources and field evidence for native_v5

The owned resource inventory is complete for the explicitly selected 16 rule prefabs and their literal buff-template references. It verifies 20 original/derived source pins and preserves serialized fields, MonoScript identities and local object references. It is not a proof that every attached component has executable behavior in the simulator.

`inventory.json` verifies **16 prefabs / 187 rule MonoBehaviours**, **21 root template keys / 22 keys after literal closure**, all from 8,659 source templates, with **zero missing literal templates**. `devices/native_fields.json` records **75 native types / 2,989 fields / 101 generic identities**, including exact native offsets, inheritance, value-type markers, sizes, method indices/tokens and metadata/native type identities. The original v4 pinned exports were preserved.

## Extraction boundaries and useful findings

- `rule_prefab_subtrees.json` traverses Transform descendants and their local rule references for ten enemies, altar, altar skill and four boxes. The older v4 PPtr-only graph omitted child dynamic Talent/Skill objects. The expanded source proves those attached declarations without treating active_self/m_Enabled as runtime initialization timing.
- `scene_templates.json` recursively resolves `templateKey`/`_templateKey`, including plain JSON node state and embedded node templates. It includes the actual original `empty` template, whose `eventToActions._items` is empty, rather than assuming a missing template inert. Computed/template keys assembled from dynamic blackboards are outside literal closure.
- `range_table.json` contains 73 ranges. Altar `x-1` has direction1 and 13 cells in a radius2 diamond. The original 55,219-byte bundle is SHA256 `d7e25893e798733810208b539bf3c13bcc42516d75342114ac4810ffae744be5`; its signed TextAsset is 53,520 bytes. Published RSA/MD5 signature validation succeeded; the pinned author converter's published offline AES constants decoded ordinary UTF-8 JSON. No key/token value was emitted, no account credential was read, and no service was contacted.
- `altar_context.json` preserves SP7, AUTO skill, .6 binary32 pre-delay, PURE500 declaration and full selector/cast fields. Tile rewrite flags are `rewrite_options=true`, keepPass=false, keepBuild=false, ignoreBlockAnyRoutes=false, rewriteHeightTypeOnMode=false; mode options declare build0/pass2. The declared height rewrite is binary32(.4). Native Token.OnSwitchMode invokes Tile.TryUpdateOptions; Trap.OnInit by itself did not prove rewrite. Effective activation timing/cache belongs to the separate movement/scene closure.
- TileData ctor raw `0x18242f990` proves native default `advancedBuildableMask=1` at+0x28. That field is absent from the level JSON/schema; treating it as0 or playerSide would be wrong. `scene_prefab_inputs.json` records serialized Tile defaults; runtime Init/preprocessing/cache are separate.
- `move_controller_inputs.json` preserves all ten enemy controllers' steering8/max-force10/half-width binary32(.2). TypeInfo slot `0x1889333a0` resolves to **BattleOptions**, static+0xbd **STEERING_ENABLED**. It was not DynamicConfig. A runtime field declaration does not establish the live flag value.
- `enemy_movement_flags.json` proves Enemy11393 `_alwaysCheckCurrentPoint` native+0x33d and exact prefab values: only `enemy_2137_shsdgo=true`, other nine=false. Each value has original bundle and component/script identity/hash pins.
- `deterministic_consts.json` resolves FieldInfo slot `0x1888a2778` through encoded usage kind4, field reference, native type and metadata default blob. Its 128-byte double array is 10^0 through10^15; blob SHA matches its generated field name. The retained older `evidence_link` annotation should be read with **native_v5/movement/raw_raw_helpers.json**, specifically System.Math.cctor; changing that annotation would change the pinned export, so the correction is recorded here.
- `scheduler_subscription_attributes.json` proves Scheduler10886 `_OnUnitDestroyed` method72143/token60119d0 and `_OnEnemyRecycled`72145/token60119d2 have **no custom-attribute declaration** in their image's matching token ranges. This does not disprove subscriptions registered through native delegates/reflection elsewhere; the EventKey-attribute hypothesis is unsupported for these two methods.

## Attached behavior which remains relevant with no operators

`enemy_shdopl_passive` has start-event SummonEnemiesFollowMyRouteWithBuff, count1/delay0/scheduler management/unharmful/host-root-tile flags and host disappearance. Its follow-up template has owner-finish and take-damage paths to host reposition/reappear/passive removal, plus summon kill/lock/clear actions. Its passive abnormal flags include INVINCIBLE/BLOCK_FREE/ALLY_TARGET_FREE. These declarations alone do not establish newborn/owner-finish event timing.

`upeople_t` has owner-killed ModifyLifePoint; the enemy database supplies dead.value=-1. `upeople_t_1` supplies the associated audio action. `enemy_1085_sotiwz_3` has Default/Rage Immo skills and ore-immune/listener related passives; its attack ability waits for an animation attack event despite pre-delay0, so zero pre-delay is not an immediate-spell proof. The rare box includes inverse-damage with atk_scale .4. Expanded templates also include shsdgo, skzjxd, duck and kill-log actions. Scene preflight must retain these active dependencies.
